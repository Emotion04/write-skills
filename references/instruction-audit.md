# 指令审计

在删减草稿或重构臃肿的 Skill 时阅读此文件。

## 证据门槛

每条保留的指令必须至少占一项：

1. **环境外信息差**：Agent 无法从代码、配置、工具或当前请求中直接推断的事实；
2. **决策偏好**：多种可行方案中，指定选用哪一种的明确偏好；
3. **硬边界与输出契约**：不可逆操作限制、范围红线或可检查的产出格式；
4. **已证实失败的防线**：防止某次真实出现过的错误重演。

四项均不占则删除。

## 有条件保留

- **分步编排**：仅当步骤顺序是硬性依赖（前一步产物是后一步前提），或模型实测会跳步时保留。不要把模型的常识思考过程写成步骤。
- **示例**：仅在纯文字规则有歧义时，保留一个最小高信噪比示例。
- **异常处理**：仅保留真实运行环境边界上大概率触达的异常，不预防假设性极端情况。
- **强调语气**：仅在普通陈述实测失效时升级语气。

## 默认删除

- 角色扮演与鸡汤式铺垫（"你是一个资深的……"）。
- 复述模型默认就会做的合格行为（"先理解需求""写出高质量代码"）。
- 仓库配置、目录结构或 `--help` 中已有的事实。
- 同一规则在不同章节的换词重述。
- 为过时弱模型打的补丁（当前强模型已不再犯的错误）。
- 无法转化为具体检查项的空泛形容词（"优雅""健壮""全面"）。

## 常见病灶与修复

| 病灶 | 表现 | 修复动作 |
|---|---|---|
| **No-op** | 删掉该句后模型输出与行为毫无变化 | 直接删除 |
| **重复** | 同一规则散落在正文、注意事项、结尾多处 | 只在最贴近操作处留一处，其余删净 |
| **沉积** | 旧报错早已修复或模型升级后不再犯，防线仍在 | 验证不复现后删除 |
| **散落** | 仅某分支用到的长篇参考塞在主文件里每次加载 | 下沉到 `references/`，主文件只留触发指针 |
| **过早收尾** | 后续分支的细节干扰了当前主线，导致模型草草结束 | 锐化完成条件；仍无效时拆分为独立 Skill |
| **纯否定式** | 只写"不要做 X"，激活了模型对 X 的注意力却没给方向 | 改为"做 Y（替代 X）" |

## 压缩顺序

1. 砍掉无证据支撑的整段与整句。
2. 合并重复含义，确保单点事实源。
3. 把确定性校验/转换逻辑抽成 `scripts/`，删掉大段文字描述。
4. 把低频分支材料移到 `references/` 指针后面。
5. 最后再精炼字句（不要美化噪音——先删噪音，再润色留存骨架）。
